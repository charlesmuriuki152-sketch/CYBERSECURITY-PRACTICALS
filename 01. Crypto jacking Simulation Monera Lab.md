Platform: Lenovo ThinkPad T430s · Windows 10 Home · Kali Linux Rolling on WSL2
Scope and accuracy: This is a lab record of the setup and commands discussed. XMRig compiled and its benchmark ran; P2Pool compiled. 1. Objective
Set up a local Monero mining lab and build P2Pool, while learning how unauthorized cryptomining (often called cryptojacking) can misuse a device’s CPU and how to recognize and prevent it. All mining should be authorized by the device owner.

Intel Core i5-3210M (2 cores / 4 threads), 8 GB RAM.
Kali Linux Rolling under WSL2; nproc reported 4 processors.
XMRig 6.26.0, built from source.

3. Commands used
Inspect the WSL environment
nproc
df -h /
Build XMRig from source
The source directory was ~/xmrig; the executable was ~/xmrig/build/xmrig.
cd ~/xmrig
mkdir -p build
cd build
cmake ..
make -j2
Benchmark XMRig
cd ~/xmrig/build
./xmrig --bench=1M
Observed benchmark: approximately 255 H/s on this laptop. This is a benchmark result, not proof of ongoing pool mining or profit.
Extract Monero CLI and create a wallet
The extracted CLI directory was ~/monero-x86_64-linux-gnu-v0.18.5.4; the wallet directory was ~/monero-wallet.
cd ~
tar -xvf monero-linux-x64-v0.18.5.4.tar.bz2
mkdir -p ~/monero-wallet
The wallet was created interactively with the Monero wallet CLI. Wallet secrets, passwords, and recovery seed are intentionally not included in this report.
Start a pruned Monero daemon
Run this in a dedicated Kali terminal and leave it open while syncing:
cd ~/monero-x86_64-linux-gnu-v0.18.5.4
./monerod --prune-blockchain --zmq-pub tcp://127.0.0.1:18083
In a second terminal, status was checked with:
cd ~/monero-x86_64-linux-gnu-v0.18.5.4
./monerod status
Observed state: synchronization was in progress. It was not confirmed complete.
Clone and build P2Pool
git clone https://github.com/SChernykh/p2pool.git ~/p2pool
cd ~/p2pool
git -c http.version=HTTP/1.1 submodule update --init --recursive --depth 1
After installing the required development dependency libcurl4-openssl-dev, the build directory was recreated and P2Pool compiled:
cd ~/p2pool
rm -rf build
cmake -S . -B build -DWITH_RANDOMX=OFF
cmake --build build -j2
Observed result: 100%] Built target p2pool; executable at ~/p2pool/build/p2pool.
Android ADB / scrcpy preparation (separate task)
The Windows tools were extracted to C:\scrcpy\scrcpy-win64-v4.1. In Command Prompt:
cd /d C:\scrcpy\scrcpy-win64-v4.1
adb.exe pair PHONE_IP:PAIRING_PORT
adb.exe connect PHONE_IP:DEBUGGING_PORT
scrcpy.exe
Use the IP address, pairing port, connection port, and pairing code currently displayed by the phone; the pairing and debugging ports are different. Do not publish pairing codes.

5. Cryptojacking: technique and defensive indicators
Cryptojacking is unauthorized use of someone else's computing resources to mine cryptocurrency. Common high-level patterns include a miner installed without informed consent, a process that repeatedly restarts after being stopped, excessive CPU use, suspicious startup tasks, and unexpected outbound network connections.
Defensive checks on Linux/WSL:
ps aux --sort=-%cpu | head
top
Check processes, startup configuration, and network activity. Investigate unknown miners; do not terminate processes you do not understand on a production system.
Prevention:
Only install miners with the device owner's explicit permission.
Download software from official project pages and verify releases where possible.
Monitor CPU temperature, utilization, power use, and network connections.
Review startup tasks and remove unrecognized software.
Keep operating systems and security tools updated.
Do not expose Monero daemon RPC to the public internet. Use a private VPN or properly secured access for authorized remote devices.
6. Important storage constraint

Check and free disk space before continuing blockchain synchronization; stop the daemon with Ctrl+C if you need to pause it. Do not delete wallet files or the recovery seed.
